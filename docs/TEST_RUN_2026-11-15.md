## 10. Fix log: P1 and P2

Sections 1–9 above are the original run and are left unchanged except for
the two status cells in §6. Only P1 and P2 were fixed. P3–P7 are untouched.

### P1: evidence references

- New `backend/app/domain/evidence.py` (stdlib only):
  - `validate_evidence_ref(ref)` accepts only a relative POSIX path of 1–8
    ASCII components (letters, digits, `.`, `_`, `-`; first character a
    letter or digit), at most 100 characters per component and 255 overall.
  - It rejects absolute paths, `..`, `.`, empty components, backslashes,
    colons (drive letters, NTFS streams), `~`, NUL and control characters,
    whitespace, non-ASCII look-alikes, trailing dots and Windows device names.
    Non-canonical input is rejected, never rewritten.
  - `resolve_evidence_path(root, ref)` requires an absolute, existing root
    directory, resolves symlinks, and rejects any result outside the resolved
    root (including dangling symlinks, symlink loops and the root itself). It
    opens and serves nothing.
- `events.py` validates `evidence_ref` with the same rules, so unsafe
  references are rejected by the pipeline and never stored.
- Remaining limits: resolution is a point-in-time check (a future file server
  must open with `O_NOFOLLOW` and re-verify); hard links cannot be detected by
  path; the evidence root is not yet read from settings (`config.py` needs
  pydantic).

### P2: failed-login under-counting

- `pipeline.py` no longer merges events by a fingerprint of their facts and a
  2-second bucket. The `fingerprint` function and the `dedupe_seconds` option
  were removed.
- De-duplication now uses only `event_id`, the producer's idempotency key. An
  event without one gets a fresh id and is always stored. A repeat of the
  same id with the same content is a retry and is stored once.
- An `event_id` reused with different content is stored under a new id, with
  the reused id in `details["event_id_conflict"]`, and counted in
  `stats.id_conflicts` and the `event_id_conflict_rekeyed` warning.
- Rate limiting (`app/core/rate_limit.py`) was not changed and remains
  separate. Redaction runs before storage on every path.
- Remaining limits: two deliveries that reuse one `event_id` and are identical
  after redaction count as one retry, by definition of an idempotency key
  (login events get server-generated ids, so a client cannot choose them).
  The pipeline remembers the last 50,000 ids; a retry arriving later is stored
  twice, which over-records rather than loses. `auth_service.py` does not yet
  emit pipeline events; it was not modified because it cannot run here.
